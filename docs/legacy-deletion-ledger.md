## 状态定义

- `DELETE_NOW`：当前非测试调用链没有消费者，可先删，但仍需跑单元测试。
- `MIGRATE_THEN_DELETE`：生产仍有消费者；先切换到替代路径，再删兼容分支。
- `CONVERGE`：多个实现同时在线；先指定唯一事实源，旧实现降为只读/观测，再删除。
- `KEEP`：不是历史包袱，属于目标架构所需的安全能力（例如正向 LKG、签名校验）。
- `ISOLATE`：有意支持 dev/test 或离线迁移，但不应继续进入生产流量路径。
- `REMOVED`：代码或资源已在当前基线删除，仅保留台账记录，避免重复安排清理。

## 不应删除的“看起来像旧逻辑”

以下不是删除对象：正向 LKG/previous serving pointer、签名和 digest 校验、CAS/fencing、artifact 原子写入、consumer heartbeat、故障时保留旧正向答案，以及 Edge 的 previous-cache/active-route fallback。对“authority CAS 已成功、executor terminal receipt 丢失”的状态做只读 reconcile 也是目标架构需要的恢复能力；P08 应先并入 canonical transaction receipt，不能直接删。Guardian 将 inactive candidate fence 在健康 LKG 上是预期安全状态，不应通过清除 fence 或绕过 Guardian 来“修复”。应删除的是重复的 current pointer、现场重新编译、DNS 冒充 Edge ACK，以及完成迁移后的事故专用 predecessor/alias 分支。

## 删除顺序与门禁

1. `DELETE_NOW`：先删死函数/死环境变量，并跑对应包测试。
2. `CONVERGE`：建立 canonical TrafficEpoch/artifact，旧入口只读双读；对每个 hostname 记录 `epoch -> bundle digest -> ACK -> DNS digest`。
3. `MIGRATE_THEN_DELETE`：完成全节点迁移、请求计数归零、LKG 窗口结束和故障注入后，再删旧消费者。
4. Guardian legacy normalization、orphan repair、candidate fencing、historical alias 和 LKG recovery 最后处理；必须先保证发布失败不影响当前 TrafficEpoch，并证明 `recovery_required`、unknown stale execution、historical alias 和 repair receipt 读取归零。
5. 每个删除 PR 必须包含：调用链变更、生产观测门禁、旧数据迁移/回滚方案、单元测试、跨节点真实 DNS/TLS/Host 检查。
