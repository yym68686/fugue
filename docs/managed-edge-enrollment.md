# Managed Edge enrollment

`fugue admin cluster node-policy set <node> --edge on --edge-group <authority>` prepares an existing joined node without moving it into the internal shared pool. An existing explicit node binding can supply the authority on retries. Country and hostname never select an authority. The command preserves application, build, DNS and sharing roles unless their own flags are provided.

A managed enrollment stores the exact current authority record, worker source/image, slot and fence with a fifteen-minute absolute admission lease. The node updater must be fresh, bound to the machine and support desired-state refresh. The initial Kubernetes Edge label is held until node credentials are acknowledged; the updater writes credentials before updating join labels. Partially enrolled static identities without runtime evidence can complete as managed identities. An established static identity or a foreign authority cannot be migrated implicitly.

The worker derives a short-lived reader identity scoped to the exact node, group, component and artifact kind. Existing static reader credentials continue to work unchanged. Private preparation requires an authenticated administrator enrollment, absent local activation and a verified current signed bundle. Existing or corrupt activation cannot fall back to enrollment. Reading the permission neither renews its lease nor creates serving authority.

The CLI inspects the exact current worker image and projected identity, verifies fresh route and TLS execution proofs, repeats the current-authority read, and uses the existing create-only Front activation CAS. It never overwrites an existing activation. Enrollment does not declare a route healthy, write LKG, select a DNS answer, increase routing weight or force a node to receive traffic. Public reachability is probed only after the node's worker health, route/TLS state and exact identity are ready. Normal route eligibility and route-quality ranking decide whether a prepared candidate receives business requests.

By default the CLI waits for the real worker slots, Front, current node policy and fresh runtime health. Failure or timeout is a nonzero result with the pending condition. Rerun the same intent after resolving it. `--wait=false` explicitly submits intent and reports `edge_ready=false`; label reconciliation is never equivalent to completed enrollment.
