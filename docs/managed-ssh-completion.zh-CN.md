## 身份问题

已确认的缺陷是：旧链路使用应用镜像内的 SSH 主机密钥，两份 Argus
容器共享主机身份，平台没有把 SSH 身份与应用镜像、实例更新隔离。
历史旧指纹被替换的完整时间链没有足够留存证据，不把推测写成根因。

现在由 Fugue 的独立 SSH 服务终止连接，身份绑定逻辑应用并加密持久化。
经用户批准，两个原端口已切换；四个公网入口核对一致后，仅替换了本机
`known_hosts` 对应记录，并保留两份备份。其他客户端需登记同一新指纹。

## 平台托管能力

| 能力 | 验收结果 |
| --- | --- |
| 原生 SSH、终端与退出状态 | 命令、PTY、窗口调整、信号及取消通过 |
| 文件与开发工具 | SFTP、现代 SCP、实际 VS Code Remote SSH 通过 |
| 转发与隔离 | 显式允许的应用回环端口可用；未授权端口、集群管理地址及跨租户访问被拒绝 |
| 授权与审计 | 公钥撤销、自然过期、连接/通道限额、审计失败拒绝执行通过 |
| 发布与恢复 | 候选验证、配置签名、LKG、升级、回滚、既有会话保留和安全退役通过 |
| 应用生命周期 | 合成应用重启后身份及端口不变；新应用端口自动发布到四个入口 |
| 运行能力 | 真实执行摘要校验后的 helper，验证 shell、PTY、信号及网络能力，不只检查文件存在 |
| 身份维护 | 五份身份与所有权锚点恢复验证通过；独立只读盘点及精确计划重加密工具已交付 |

五个应用分别通过四个入口的认证会话验证，共 20 条公网路径，并与每个入口
自己的实例 ACK 对应。运行镜像为
`ghcr.io/yym68686/fugue-managed-ssh@sha256:d41c707e41027e1483d95da2a5d6c19e5270074b2f8f2dfc205b4ebe2b0cfcd9`。
身份、授权、签名配置、运行事实与执行镜像分别管理；失败候选保留已验证状态，
但不会借 LKG 延长已撤销或已过期授权。

当前运行适配器要求 Linux、匹配架构的 helper、配置的 shell、基础引导工具
及可写可执行临时目录；在容器当前用户下执行。生产已验收 amd64。
现代 SCP 使用 SFTP；不支持 `scp -O`。会话不能跨越业务进程或节点本身的丢失。
应用原生 SSH 不属于此次迁移范围。

## 延长观察发现并处理的问题

一次旧服务器上的验收会话在授权到期后断开：旧授权于
`2026-10-11T16:14:33.052763469Z` 到期，新授权于 `16:14:35.360150247Z`
才加载。现已把授权发布提前到慢速运行检查之前，提前续期，减少重复资源写入，
并为控制器声明共享、有上限的 Kubernetes 请求预算；授权期限仍为五分钟。

三条认证会话连续运行 631.451 秒，跨过多个授权代次，没有断开；最低采样
剩余有效期为 107.327 秒。另有 Argus 会话跨越后续控制器更新保持可用。
请求预算修复后，观察窗口内客户端限流超时与限流等待日志均为零。

退役校验还存在查询前取时钟的问题，会把慢查询期间到达的有效 ACK 误判为未来
时间。修复在全部读取完成后统一校验时间；延迟回执、读取期间过期及真正未来
时间三类测试通过，未放宽身份、路由、现存连接或回滚保留期的检查。
